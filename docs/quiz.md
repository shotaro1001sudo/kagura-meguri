# 神楽の好み診断（2026-11-09 改訂）

`/quiz.html`。実行時AIや外部APIを使わず、ブラウザ内のメモリで判定する。回答・条件・結果は保存/送信しない。性格・適性・相性の確率を判定するものではない(「物語派」などの呼び名は、回答で選んだ観かたのまとめで、人の性格ではない)。

## 質問

`scripts/lib/quiz.mjs` の質問定義が、順序・選択肢・件数の共通元。全9問、すべて「まだ分からない」を選べる。

- 好みの6問(採点): 見てみたい場面、舞のテンポ、目が離せないもの、観る時間、客席での楽しみ方、観終わったあとの余韻
- 案内の希望1問: 結果の補足だけに使い、順位を変えない
- 地域・日程の2問(任意): 好みの順位は変えず、観に行ける公演を探すためだけに使う。地域は都道府県のほか「中国のどこでも」のような地方まとめ(`地方:中国`)も選べる。日程は今週末・今月・来月・日付指定

各採点の選択肢は合計1点。2つの好みにまたがる選択肢は 0.5 ずつ配る。「分からない」は0点。

## 好みの軸と、種類の特徴(根拠)

好みの軸は12個(速く勇ましい舞・古式ゆかしい舞・神話の物語・面や衣装の華やかさ・大蛇や鬼の登場・祭りや神事の空気・夜を通して舞う神楽・湯立て・笑いや曲芸・観客も加わる場面・囃子や歌の響き・気軽に観られる公演)。

対象は `data/kagura-info.json` に出典つきの解説がある19種類(紹介文だけの安芸高田神楽は、広島神楽と重なるため対象外)。`traditions.evidence` の各特徴は、解説の本文のフィールドに結び付ける。`intro~1` は紹介文の2文目だけ、`tagline` は「地域 ・ 」のあとの一言だけを根拠として示す。フィールドが空・未知の特徴ならビルドを停止する。**根拠のない特徴は加えない**(例: 春日若宮おん祭は「真夜中に行われる神事」はあるが、夜通しとは書かれていないので「夜を通して舞う神楽」にしない)。既存の出典内容を公式サイトで再監査したことは意味しない。

特徴の強さは機械的に決める: 根拠が紹介の中心(tagline / intro)なら2、features・programs・viewing・history なら1。同じ特徴に根拠が複数あっても、強いほう1つだけを数える。

## 採点(好みの近さ)

回答から好みのベクトル(軸ごとの合計)を作り、種類の特徴ベクトルとの**コサイン類似度**で比べる。特徴の数が多い種類ほど点を取りやすい、という旧版(単純な足し算)のかたよりをなくすため。最大3種類を表示し、同点は定義の掲載順で安定させ、同点がある旨を示す。点数や一致率は利用者へ示さない。全部「分からない」なら特定の種類を推薦しない。

テスト(`tests/quiz.mjs`)で、採点6問の全組み合わせ(4,800通り)を総当たりし、19種類どれもが1位になりうること、1位になる組み合わせが全体の2割を超える種類がないことを確かめる(2026-11-09時点で、各種類 1.7%〜13.5%)。種類ごとの特徴の組み合わせが、すべて違うことも確かめる。

## 結果

1. 好みの傾向: 回答で多く選んだ軸の上位2つの呼び名(例「物語派 × 迫力派」)と、その説明。上位5つの軸をタグで示す
2. いちばん近い神楽: 一言紹介、回答の好みと重なる特徴(好みの強い順に最大3つ。根拠の本文をそのまま示す。同じ本文は1つにまとめる)、観に行くときのヒント(解説の「見学のコツ」から、理由と重ならないもの最大2つ)、出典、解説ページへのリンク
3. こちらも好みに近い神楽: 残り2種類を、理由1つずつ
4. 観に行ける公演: 上の3種類の掲載公演を、地域・日程で絞って最大6件。該当がなければ、条件で観られる種類のうち好みに近いものを「好みの近さは上の神楽より下がる」と明記して示す。定期公演は別枠の参考情報
5. シェア: Xの投稿画面へのリンクと、文面のコピー。押したときだけで、文面は好みの傾向といちばん近い神楽の名前。URLは `/quiz.html` だけで、回答や結果をURLに入れない(GA4のページURLに結果が載らないように)

ページ下に「診断のしくみ」と対象19種類の解説へのリンクを静的に載せる(JavaScriptなしでも読め、検索にも出る)。

## 公演の条件

日本時間で再評価する。終了時刻ありは終了まで、終了なしは既存サイト同様に開始後3時間、時刻不明は終了日(なければ開始日)の当日まで候補に残す。これらは掲載期限であり、実際に開催中と保証するものではない。日またぎも期間の重なりで扱う。今週末は、平日なら次の土日、土曜は当日から、日曜は当日だけ。

「1時間ほどで気軽に」を選んだときだけ、各公演に掲載時間枠の確認事項を示す(候補は除外しない)。時刻不明・終了なし・複数回・複数日は所要時間要確認。定期公演は地域と掲載期限のみ確認した参考枠で、希望日の開催や時間への適合を主張しない。該当なしでもカレンダーへ進める。

## 入口

`/quiz.html`、日本語フッターの手動リンク、および公演検索/一覧/詳細の小型モデルレス案内。英語、フォーム、規約類、診断自体には自動案内を置かない。

案内文は「気になる神楽、まだ迷っていますか？」「好みから探す」「閉じる」。PCは可視閲覧30秒以上＋120px以上スクロール後、ポインターが画面上端を出た場合。スマホは可視閲覧30秒以上＋スクロール可能範囲の半分以上（最低200px）閲覧後、上方向へ200px戻った場合。単なる滞在、非表示タブ、公式リンクのクリック、戻る操作では表示しない。これらは読み終わり・離脱意向の推測であり、本当の退出を検出するものではない。

同一タブの既存sessionStorageキーに表示済みフラグだけを保存し、表示は1回。閉じても再表示しない。保存不可では表示しない。入力フォーカス・編集済みフォーム・表示中ダイアログ/Cookiebotを避け、後からCMPを開いた場合も閉じる。英語/規約/問い合わせ/掲載フォーム/診断ページは対象外。

非モーダルのaside領域を用い、表示時にフォーカスを動かさない。Escape/閉じるで解除し、カード内にフォーカスがあった場合だけ元の操作へ戻す。広いPCで本文右に372px以上の空きがある場合のみ右下に置き、下端の固定/追従操作部を避ける。それ以外は閲覧箇所の本文の区切りに挿入し、本文を覆わない。カードが画面高さの45%を超える等、安全な表示場所がなければ表示しない。スクロール固定・自動スクロールはしないため、挿入位置によってCTAは少し下にスクロールして見える場合がある。

`beforeunload`・履歴追加・戻る横取り・リンク阻止は使わない。[ChromeのPage Lifecycle解説](https://developer.chrome.com/docs/web-platform/page-lifecycle-api)と[MDN beforeunload](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event)が説明する、特にモバイルで終了イベントを確実に受け取れない制約を踏まえる。戻る・非表示時に新しい案内を開く設計ではない。

案内用の新規計測イベントは追加しない。既存の診断開始・完了・公演遷移でしか効果を確認できず、案内単体の表示率やクリック率は現状計測できない。

## 画面・検証

全問で明示的な「次へ」を押す。選択だけの自動遷移はせず、タッチ/キーボードで同じ操作にする。前へ戻って修正でき、やり直しで回答・条件を消去する。進捗と件数は質問配列から算出。地域はネイティブselect(地方ごとのoptgroup)、指定日はdate入力。非表示フォームの二重送信は無視する。

単体/生成DOM検証: 全不明・同点・根拠対応・総当たりの到達性とかたより・条件の採点分離・不正日付・今週末/月末/年末/うるう年・開催中/日またぎ/時刻不明・地方まとめ・0件と代わりの候補・再集計/戻る/やり直し・同意/自己除外・個別情報非送信・シェアURL。実ブラウザの表示/キーボード検証は別途記録し、本番確認と区別する。
