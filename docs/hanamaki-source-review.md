# 花巻情報源：検証準備

対象は既存候補 `hanamaki-hayachine` の「おおはさま神楽の日」のみ。候補アダプタと書込を行わない `node scripts/probe-hanamaki.mjs` を追加した。元のsources.jsonは変更せず、enabled=false・termsChecked空欄のまま。通常の週次収集へは接続していない。

## 調査で見つかった不確実性

- [公式イベント一覧](https://www.kanko-hanamaki.ne.jp/event/)の月別入口は年をURLに含めない。
- [11月の詳細 id=1060](https://www.kanko-hanamaki.ne.jp/event/event_detail.php?id=1060)は、検索結果と取得した本文で年が一致しない例があった。本文の開催日欄では2023年11月12日となっており、2026年に読み替えない。
- 本文の開催時間には開場・休憩も含まれるため、括弧内を開演時刻として扱わない。
- robots.txtとBot UAでの実HTML取得は実行環境のプロキシ接続不能で未確認。プライバシーポリシー閲覧だけで自動収集の利用条件を確認済みとは扱わない。

## 検証の境界

単体テストのHTMLは合成サンプルで、公式の実HTMLの保存・検証ではない。アダプタが実ページの構造に合うかは未確認。複数日・不正日付・年なし・欠落ラベルは停止する。紹介本文や画像、連絡先情報は取り込まない。

dry-runはJSTの今月から3か月、同一オリジンの詳細記事12件まで。robotsを各URLで確認し、redirectを拒否、3秒間隔。0件やページ構造変更は成功扱いしない。データ/設定/Actionsの変更・有効化・公開を行わない。取得結果のguardと既存の公演/定期公演との重複候補を報告する。

## 有効化前の残件

1. 利用条件・robotsを実際の配信元で確認。
2. Bot UAの実HTMLで月別一覧と詳細を照合。年・開演/開場・会場の一致を確認し、必要ならセレクタを調整。
3. 既存定期公演との意味上の重複を人が確認。URL/名称の機械検査だけで重複なしとはしない。
4. 月別巡回と記事発見を通常collectorへ接続する方式を別PRで検証。現行collectorのdiscoverは最初の一覧に限定されるため、単にadapter名とenabledを変更してはならない。
5. 実検証の根拠がそろった後に有効化PR、CI、公開、PC/スマホQA、初回週次runを確認。

新規サービス・有料API・追加購入なし。手動Actionsは起動しない。
